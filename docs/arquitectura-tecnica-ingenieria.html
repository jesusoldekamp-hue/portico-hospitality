Flujos de ejecución y backlog de hardening de producción (Página 2 de 2)

3. Secuencias críticas de ejecución (Anexo 2 DOF y propiedad de no-interferencia)

Flujo A: Activación entrante SEGOB (Fases 1, 2 y 3)

  1. Auth M2M: SEGOB llama POST /api/pui/:slug/login; servidor valida clave_pui_hash con scrypt + timingSafeEqual y firma JWT HS256 (exp = 3600s) acotado a hotelSlug + rfc.
  2. Validación de Scope: En /activar-reporte o /activar-reporte-prueba verifica firma JWT, expiración y payload.hotelSlug === :slug (rechaza cruces entre RFC con HTTP 401).
  3. Cifrado e Indexación: Valida dígito RENAPO, deriva blind index HMAC-SHA256(slug::CURP) y cifra CURP en AES-256-GCM; ejecuta upsertAlert(..., activa=1) (arma Fase 3).
  4. Barrido Histórico (Fase 1 y 2 ≤12 años): Consulta findGuestsByCurpHash() sobre idx_guests_lookup y encola respuesta positiva o cierre negativo en segob_outbox.
  5. Entrega Asíncrona (puiClient.js): Worker cada 5s autentica con caché JWT (30s skew, purga en 401) y despacha POST /notificar-coincidencia con timeout 10s y backoff exponencial (máx. 8 intentos).

Flujo B: Check-in en vivo, Menores LGT y Sigilo

  1. Ingesta Unificada: Llega check-in vía API REST, pms-sync-agent.js (autodetección UTF-8 vs Latin-1 0xFFFD para XML/CSV/Pipe/.prn) o Terminal Web.
  2. Identidad y Minoría de Edad: curp.js / mrz.js validan documento ($0) y derivan edad exacta. Si edad < 18 y falta parentescoDocumento (o es NO_ACREDITO), aplica bloqueo Art. 58 LGT.
  3. Persistencia Cifrada: Inserta en guests con curp_hash (HMAC) + curp_cifrada_json (AES-256-GCM) y CURP enmascarada para vistas operativas.
  4. Frontera de No-Interferencia: evaluarAlertasFase3() cruza curp_hash contra idx_pui_alerts_lookup(hotel_slug, activa, curp_hash). El resultado nunca entra en el JSON HTTP devuelto a RECEPCION.
  5. Despacho Silencioso y Auditoría: En caso de hit, encola Fase 3 en segob_outbox (prioridad CRITICA_MENOR si <18), dispara procesarColaOutbox() y encadena registro en audit_log (SHA-256).

4. Threat Model y Backlog P0 (Bloqueantes obligatorios antes de recibir PII real)

P0-1 Envelope Encryption y Fail-Fast (src/security.js:11-14) Hoy existen fallbacks hardcodeados de dev para PUI_JWT_SECRET y PUI_VAULT_KEY, y una llave única compartida. En producción: fallar al arranque si faltan secretos, usar AWS KMS con DEK por hotel + columna key_version para rotación segura sin romper blind indexes, y desactivar PORTICO_DEMO_MODE + rutas /api/demo/*.
P0-2 Cableado real a PostgreSQL 16 + RLS + SKIP LOCKED src/db.js corre en node:sqlite (single-node); db-adapter.js ya define el wrapper RLS pero requiere migrar los queries a pg.Pool con rol NOBYPASSRLS + FORCE ROW LEVEL SECURITY, usar FOR UPDATE SKIP LOCKED en segob_outbox para multi-réplica ECS y particionar guests con pg_partman.
P0-3 Perímetro M2M exclusivo para SEGOB Terminar TLS 1.2+/1.3 con Strict-Transport-Security (HSTS), colocar /api/pui/* detrás de AWS WAF + IP Allowlist de SEGOB/ATDT (y mTLS si lo soporta la autoridad) y validar que ningún endpoint administrativo quede expuesto en la misma superficie pública.
P0-4 AuthN Web, CSRF y Rate Limit distribuido rateLimit.js usa un Map local en memoria: migrar a Redis (ventana deslizante atómica). Agregar TOTP MFA + lockout en cuentas ASOCIACION_ADMIN / HOTEL_ADMIN, validación Origin + token CSRF en mutaciones por cookie y alojar fuentes localmente (sin CDNs externos en CSP).
P0-5 Hardening del Agente Local (agent/pms-sync-agent.js) Actualmente permite http:// por defecto (:139) y retiene CSV/XML en texto plano en processed/ y failed/ (:99-111). Exigir https:// con verificación estricta de certificado, borrado seguro inmediato tras HTTP 200 (sin PII residual en PCs de mostrador) y rotación automática de API Keys.
P0-6 Contrato exacto Sandbox ATDT (SG_230126_VES_02.pdf) Al obtener credenciales de Etapa 1 (Llave MX + e.firma del hotel piloto), validar campos exactos de payload, códigos HTTP, política de firma JWT (HS256 vs RS256/JWKS) y endpoints de callback reales mediante /activar-reporte-prueba.

5. Backlog P1: Validación de identidad externa y certificación Sección 8

P1-1 Autenticidad RFC (SAT): validar cadena X.509 del certificado público .cer (FIEL/CSD) o QR de Constancia de Situación Fiscal al dar de alta cada hotel real.   P1-2 Consulta Nivel 3 opcional: adaptador desacoplado para confirmar vigencia/titularidad CURP contra RENAPO o Lista Nominal INE cuando un hotel lo solicite.   P1-3 Gate CI/CD Sección 8 + LFPDPPP: SAST (Semgrep/CodeQL), DAST (OWASP ZAP), SCA (Trivy sobre imagen Docker) con cero hallazgos críticos/altos + contrato de Encargado de Tratamiento de Datos firmado con cada hotel.
